# Data Intake & Validation（数据接入与校验）模块 · 业务流程说明

> 用业务语言描述 S2 阶段每个环节"做什么、谁来做、背后依据什么逻辑"，不涉及技术接口。
> 文中的阈值、判定规则均与当前实现一致（已逐条对照代码核验）。

---

## 一、模块定位

S2 是整个 MMM 项目的**数据质检车间**：上游（S1 业务理解）产出**因子树**——业务上认为可能影响销量的所有因素；下游（S4 建模）需要一张干净、可信、每个字段都经得起追问的**主数据宽表**。S2 的职责，就是把已准备好的数据资产逐层校验、筛选，最终锁定这张建模输入表。

**阶段里程碑：Master Data 锁定（主数据锁表）。**

### 两条设计主线

**主线一：每个交付物都是"AI 提案 → 人审核 → 关卡放行"的过程**，而不是一次性产出。AI 负责算证据、给建议、写理由；人负责裁决；关卡确保没人看过的数据不会流入下一步。

**主线二：指标生命周期六层过滤。** 每个指标必须依次通过六道关卡才能进入模型：

| 层 | 关卡 | 淘汰原因（业务语言） |
|---|---|---|
| ① 映射 | 2.1 数据处理 | 该因子被明确标记为"忽略"（确认无数据） |
| ② 质量 | 2.2 质量评分 | 人在评分表上把该指标判为 **Drop**（数据不可用） |
| ③ 业务签核 | 2.3 业务校验 | 客户对该因子明确标记"未签核" |
| ④ 统计 | 2.4 统计评分 | 人在评分表上把该指标判为 **Drop**（统计特征不适合入模） |
| ⑤ 变量选择 | 2.5x 建模变量 | 人在变量清单上没有勾选它 |
| ⑥ 区间校验 | 2.5r 试拟合 | ROI/贡献越界且人裁决"剔除越界指标" |

**"一票否决、终身继承"**：任何一层淘汰了某个指标，后面所有层直接继承该裁决并标记为"已在第 X 层否决"——它不会被重新评分、不会被重新推荐、更不会悄悄回到模型里。这一点在界面上是**看得见的**：在 2.5x 变量勾选页，上游被淘汰的指标以**划线锁定行**呈现，并直接标注"Ignored at 2.1 / Dropped at 2.2 / Not signed off at 2.3 / Dropped at 2.4"，勾选框置灰不可点。

> **一个重要的产品事实**：真正决定指标去留的，是人在评分表上**逐行**按下的处置按钮（Accept / Flag / Drop、Include / Review / Drop），以及变量清单上的勾选。关卡上那些"接受裁决 / 重新收集 / 剔除"式的选项，是给人做整体判断和流程走向用的（例如选"重新收集"会把流程回退到 2.1 重做），**它们本身不会批量改变任何指标的去留**。

## 二、逐环节流程

### 环节 2.1 · Data Processing（数据处理 / 映射对齐）— 人机协作关卡

**做什么**：把"业务想要的"（因子树上每个因子）与"实际有的"（数据引擎中已发布的数据资产）对上号。

**怎么操作**：AI 为每个尚未匹配的因子推荐最合适的已发布指标（依据名称、因子路径、单位、覆盖度综合打分并排序候选）；人对每条做三选一——**接受** / **换绑**（从候选换一个）/ **忽略**（确认无数据，明确放弃并留下说明）。

**三种状态与各自后果**：
- **已映射**：找到覆盖该行的已发布指标（匹配优先级：行 ID 精确匹配 → L1–L4 完整路径 → L3 + 指标名）。
- **已忽略**：**没有**任何指标覆盖它，且人明确把它标为忽略。注意优先级——**一旦被数据覆盖上，就不可能被"忽略"，映射优先**。只有"已忽略"会在第 ① 层淘汰指标。
- **待处理**：既没匹配上也没被忽略。它**不淘汰任何东西，但会卡住关卡**。

**放行条件**：因子树上不留任何"待处理"行——每个活跃因子要么已绑定数据、要么已被明确忽略，关卡才打开，S2 正式开始。

**底层逻辑**：宁可显式放弃一个因子，也不允许"默默没有数据"。忽略是一个有记录、有理由的业务决定，而不是遗漏；被忽略的因子照样进入最终漏斗统计，不会让账对不上。

---

### 环节 2.2 · Data Quality Score（数据质量评分）— AI 执行

**做什么**：对每个指标（细到 L1×L2×L3×L4×指标）做数据质量体检。

**评分框架**：四个维度、共 10 项子检查，均按 0 / 0.5 / 1 三档打分：

| 维度 | 子检查 | 关注什么 |
|---|---|---|
| 一致性 | 维度 / 时间 / 口径 | 前后口径是否一致（换源后同比突变超 30% 判口径异常；偏离主时间轴超 10% 判时间不一致） |
| 准确性 | 数值 / 业务 | 错误值占比（>10% 判 0，5–10% 判 0.5）；花费、销量这类不该为负的指标出现负值 |
| 完整性 | 字段 / 数据 | 字段是否配套（有花费就该有对应表现指标）；覆盖时长（≥24 个月得 1，12–24 个月得 0.5，不足 12 个月得 0） |
| 粒度 | 时间 / 建模 / 下钻 | 是否满足建模所需的时间与维度粒度 |

**计分规则**：维度分 = 该维度**最弱的"阻断型"子检查**（部分子检查标为"仅供参考/需外部凭据核对"，只展示、不拉低分数）。总分 = 四个维度的**乘积**——业务含义是木桶效应的极端版：任何一维为 0，指标即不可用；有一维 0.5，总分直接减半。

- 总分 = 0 → **不可用**，默认处置 Drop
- 0 < 总分 < 0.5 → **边界**，默认处置 Flag
- 总分 ≥ 0.5 → **通过**，默认处置 Accept

**AI 的边界**：所有子检查证据与基准分由确定性规则从真实数据算出。AI 只做两件事——在这些证据之上复核四个维度分，并为每个维度写一句 ≤90 字符的评语。AI 返回的分数会被强制归到 {0, 0.5, 1} 三档，解析失败则回退到计算值；**AI 不能设定总分**（总分永远是乘积重算）、**不能设定判定、不能设定处置**。若未配置大模型，计算结果原样成立，产物上会注明本次是"AI 评分"还是"规则代评"。

---

### 环节 2.2d · Review data quality verdicts（质量裁决复核）— 人的关卡

**做什么**：人逐行复核 AI 评分并落定处置。

**怎么操作**：在评分表上逐行按 **Accept（接受）/ Flag（存疑保留）/ Drop（剔除）**，可展开查看该指标 10 项子检查的具体证据。系统按判定预置了默认值（通过→Accept、边界→Flag、不可用→Drop），人可逐行改。

**三种处置的真实后果**：
- **Accept**：正常进入下一层。
- **Flag**：**照样进入模型**，但一路带着"边界质量、保留但存疑"的标签——这是"带警示通过"，不是淘汰。
- **Drop**：进入终身淘汰名单——2.4 不再为它算统计分，2.5 不再把它列为候选变量，主数据表里永远不会出现它。

关卡上还有"接受裁决 / 重新收集 / 剔除边界指标"三个选项，用于表达整体走向：选"重新收集"会把流程**回退到 2.1** 重做这批数据（工期顺延）；其余选项不改变逐行处置的结果。

### 环节 2.3 · Business Validation（业务校验）— AI 辅助生成

**做什么**：把通过质量关的数据做成业务人员看得懂的图，逐因子体检。

**页面形态**：一个因子（L1 › L2 › L3）一张卡片。底图是恒定的**销量（sell-out）面积图**作背景，该因子的指标叠加其上——花费类画柱状、其余画折线——下方配年度与同比表格。所有曲线都是**实时查询**出来的，不是产物里的死数据。

**可下钻/筛选的维度**：
- **因子深度 L4 → L5 → L6 → L7 → L8 级联下钻**：每一级的选项由上一级选择动态算出，某级没有选项时该下拉框直接隐藏（不出现空菜单）；当前下钻路径以面包屑呈现，并与图表、表格、导出共享。
- **指标**：选择叠加哪些序列（默认最多 6 条）。
- **数据来源**、**时间粒度**（年 / 半年 / 季 / 月，只有数据确实有月度轴时才提供更细粒度）、**模型维度**（品牌 / 渠道类型 / 省份组）、**KPI 底图**（当项目同时有销量型和金额型 KPI 时可切换，默认优先销量型）、**时间窗**（见下）。

**一条重要的筛选规则**：时间粒度和模型维度会同时作用于底图和叠加线；而**数据来源筛选只作用于叠加线**——销量底图始终是完整大盘。这样无论看哪个来源的数据，都能对着同一条总销量曲线做判断。

**"来源"是怎么来的**：不是任何人手填的。数据加工流程在读取每一份原始文件时就自动打上来源印记，并让这个印记穿过整条加工链路（做关联时保留，做聚合时并入分组键，除非该步骤明确声明要合并来源）。因此图上每条线都能一路追溯回它来自哪个文件。

**AI 的边界**：因子分组、默认指标集、异常检测、以及那句解读的**计算版本**全部由规则算出；AI 只把解读句子**重写为一句 ≤20 词的英文**，且被要求"仅基于给定的数字与指标"。**AI 不产出任何数字、任何序列、任何异常、任何签核结论**。没有大模型时，计算版解读原样保留。

#### 时间窗（Time Window）

时间窗是一个**保存下来的、命名的分析周期**：一个当前区间（精确到月）、一种对比方式、以及系统自动推出的对比区间。人在业务校验页顶部的时间窗条上设置，所有因子卡片共用同一选择。

对比方式有三种，都由系统算好而不是手填：**同比**（当前区间整体前移 12 个月，长度与季节相同）、**环比**（紧邻的等长前一区间）、**自定义**（手填区间）；也可以不做对比。系统会校验两个区间是否等长，避免拿 12 个月和 9 个月对比。

设置时间窗后，整个图表视图（图、指标选项、年度表）都被限定在当前区间内，同时额外给出一块**当前 vs 对比**的数据：每个指标的本期值、对比期值、变化百分比——每个指标按**自己的**汇总规则汇总（比例类取平均、花费与销量类求和）。这个定义保存后由业务校验与后续报告共用，避免两处各手填一遍日期而对不上。

### 环节 2.3a · Explain the anomalies（异常解释）— AI 提案、人裁决

**做什么**：对数据中的显著异常逐个立案、解释、定处理方式。

**异常怎么找出来**：在销量类指标上按渠道类型计算逐年同比，凡**同比变动绝对值 ≥ 40%** 即视为异常，按幅度排序**取前 8 个**立卡。

**AI 提什么**：每张卡片给出一句 ≤25 词的业务成因假设，和一个来自**封闭三选一**的处理建议。AI 被明确要求"若无法基于数据说明，就说这次变动无法解释"，且"不得编造事件"；返回值超出三个选项会被强制归位。卡片上的方案说明与权衡文案是固定的产品文案，不由 AI 撰写。

**人裁决**：可切换处理方式、**编辑异常的起止月份**（客户确认具体日期后收窄窗口）、然后 Accept 或 Reject。卡片初始一律是"待裁决"。

**三种处理的真实效果**（关键——人的裁决会真实改变模型）：
- **结构性事件（event）**：在该时间窗内加入一个 0/1 事件控制项，把这段异常单独解释掉，避免它被误记到营销投放头上。
- **封顶（cap）**：在该窗口内把**被解释变量（销量）**缩尾到序列自身的 95 / 5 分位之间，然后再建模。
- **保持原样（raw）**：数据不动，作为注意事项带进最终报告。

**只有被 Accept 的卡片才生效**：待裁决和被 Reject 的卡片对模型没有任何影响。

> 需要知道的一个实现现状：事件项只存在于回归的控制变量中，缩尾也只作用于拟合流程；**2.6 主数据表里的销量列是未缩尾的原值**。看主数据表时请以此为准。

### 环节 2.3s · Record client sign-off（客户签核）— 人的关卡

**做什么**：逐因子记录客户对校验后数据的签字确认。页头实时显示"已签核 X / N"。

**怎么操作**：顾问与客户在图表页上**按 L3 因子**逐个签核。被明确标记为**"未签核（no）"**的因子，连同它名下的**全部指标**一并被排除出模型，并一路继承到主数据表。

**注意**：只有**明确标记为"未签核"**才会排除；**尚未签核（留空）不等于排除**——留空只表示这件事还没做。

**底层逻辑**：没有客户背书的数据不进模型。这是咨询交付的合规底线。若客户提出阻断性问题，流程回退到 2.3 重新校验。

---

### 环节 2.4 · Statistical Score（统计评分）— AI 执行

**做什么**：对仍然存活的每个指标做三项统计体检，判断其入模资格。

| 检验 | 业务含义 |
|---|---|
| **波动性 CV** | 一个几乎不变的指标，解释不了销量的起伏 |
| **相关性 Pearson** | 该指标与销量到底有没有关系、方向对不对 |
| **共线性 VIF** | 该指标是否与其他指标高度重复——两个指标讲同一个故事时，模型分不清功劳该记给谁 |

三项各自映射到 0 / 0.5 / 1 / 2 档，**总分 = 三项之和**：

- 总分 **≥ 3** → **Good（好）**，默认处置 Include
- 总分 **1.5 – 3** → **Acceptable（可接受）**，默认处置 Review
- 总分 **< 1.5** → **Unconsiderable（不可考虑）**，默认处置 Drop
- 另有一条硬规则：**VIF ≥ 10（严重共线）一律建议剔除**，不论总分多高——因为高 VIF 会抬高总分，但恰恰说明这个变量该拿掉。

**为什么已淘汰指标不参与本轮评分**：这不是省事——共线性是拿全体指标一起算的，把"死指标"留在池子里会虚假抬高活指标的共线性，导致误杀。

**AI 的边界**：三项统计量、分档、判定、剔除建议全部由计算得出；AI 只为每个指标写一句 ≤22 词的入模利弊陈述，且被明确要求"不得编造数字"。**没有任何 AI 产出的值会进入分数或判定。**

**两处诚实披露**：自动剔除建议只在总分确实很弱时触发，不因单纯 VIF 高就自动剔（整批一起算时共线本就常见）；当指标数多于月度观测数时，产物会直白说明此时 VIF 只是两两近似值，因为完整的多元 VIF 在数据量不足时无法识别。

---

### 环节 2.4d · Review statistical verdicts（统计裁决复核）— 人的关卡

**怎么操作**：在评分表上逐行按 **Include（入模）/ Review（待议）/ Drop（剔除）**，每行并列展示 CV、Pearson、VIF 与判定。

**真实后果**：**只有 Drop 会淘汰指标**；**Review 在筛选上等同于 Include**——它是给人留的标记，表示"这条还需再议"，但不影响它继续往下走。被 Drop 的指标终身继承，2.5 不会再把它作为候选变量提供出来。

关卡上的"保留可接受档 / 只留 Good 档 / 逐条人工挑选"三个选项同样是走向表述，逐行处置才是生效的那一层。

---

### 环节 2.5 · OLS Regression Test（OLS 回归测试）— 五步走的一个交付物

正式建模前的"彩排"：用一个轻量回归把选出来的数据试跑一遍，看结果是否落在业务常识范围内。拆成五步，AI 先把能提案的都提案好，人逐项确认。

**这五步里没有任何大模型参与**——全部是确定性计算，人读到的推荐理由是用真实统计量套模板拼出来的，不是生成的。

#### 2.5（第 1 步）· 提出建模方案 — 系统提案
为每个建模对象给出**因变量 Y 候选**（含单位与覆盖月数），把**自变量 X 候选**按 2.4 的统计成绩排序，并预填变换与趋势/季节设置。

**预勾选规则**：|相关系数| ≥ 0.1、VIF < 10，按相关性取**前 8 个**（在约 34 个月的序列上保住自由度）。若没有任何变量能过这道门槛，系统会把现有最好的几个预勾上，并直白写明"仅作起点，没有变量通过门槛，请先复核再采信拟合结果"——**不掩饰失败情形**。上游已淘汰的候选永远不会被复活。

#### 2.5y（第 2 步）· 确认因变量 — 人确认
为每个建模对象选定 Y。推荐用**销量型 KPI**（系数直接落在销量单位上，好解释）；若选金额型指标（或后续设定单价），ROI 才是真正的"增量收入 ÷ 花费"比值。

#### 2.5x（第 3 步）· 审定建模变量 — 人勾选
人逐个勾选进入回归的变量。每个候选旁边摆着它的完整档案：与销量的相关系数、VIF、CV、2.4 判定，以及一句理由。页头实时显示"已选 X / N"和**参数预算**（变量数 + 控制项 + 截距），超过约 20 个参数会黄色告警提示"序列较短时变量越少越可靠"。

**这是人主导变量筛选的主战场**：没被勾选的候选在第 ⑤ 层淘汰；上游已淘汰的以划线锁定行展示、不可勾选；尚未出现在候选清单里的指标算"待定"，不算淘汰。

#### 2.5p（第 4 步）· 确认模型设置 — 人确认
确认三类设置，界面对每个选项都标注了代价：
- **延迟效应（adstock）**：广告投放的影响延续多久。
- **饱和曲线**：Hill 曲线（投放加倍效果不会加倍，均值处边际递减）或线性（无递减）。
- **趋势与季节控制项**：线性趋势吸收长期漂移，不加则"趋势会漏进营销变量"；季节可选 Fourier 项（形状平滑、省自由度）、月度哑变量（完全灵活但要花掉 11 个参数）、或不加（"季节波动会漏进营销变量"）。

**业务意义**：让"大盘自然增长"和"季节波动"由专门的控制项吸收，而不是被错记到营销投放头上——这是保证基线为正、营销系数方向正确的关键。

#### 2.5r（第 5 步）· 试拟合与区间校验 — 计算执行 + 人裁决

按确认好的方案跑回归，每个指标拿到系数、t 值、p 值、ROI、贡献率，回填到因子树上。指标在多个建模对象中出现时，取各对象的平均值，t 值取最强的那个；**|t| ≥ 2.0 视为显著**（约对应 5% 双侧水平）。

**与什么区间比对**：每个指标对应一条行业经验带——预期 **ROI 区间**与预期**贡献率区间**。取值优先级为：① 项目所属行业的**知识库因子树模板**中 (L4, 指标) 精确匹配（行业二级细分优先于一级）；② 知识库中仅按 L4 匹配（先精确后模糊）；③ 参考规则库兜底。每行都会标明这条判断依据的是**你自己的行业知识包**还是**通用默认值**，让人知道结论的分量。

**什么算"越界"**：ROI **或**贡献率任一落在带外即标记为待复核，并写清越界详情（例如"ROI 2.4 超出 0.8~1.3；贡献 9% 超出 0%~1.5%"）。

**一条重要的防误判规则**：只有当拟合确实产出了**金额/花费**口径的比值时（Y 是金额型，或 Y 是销量型且设定了单价），ROI 才参与区间比对。"每元带来多少销量"与金额型经验带不可比，这类行不会被拿去比、也不会被误标越界。

**每行的状态**共六种，优先级从高到低：已被上游淘汰 → 无可用模型指标 → 无经验带可比 → 越界待复核 → 区间内。**所有活跃因子行都会列出来，包括已被上游淘汰的**，并标明是被哪一层淘汰的——刻意如此：把被拒变量藏起来，人就无从知道变量去哪了、谁决定的。

**人裁决三选一**：
- **确认选择**：入选指标进入主数据表；
- **剔除越界指标**：把越界指标物理排除后再组装主表；
- **重新审视业务假设**：若越界说明业务理解有问题，流程回退到 2.3。

> **一条关键的审计规则**：选择"剔除"的那一刻，被剔的指标名单会被**冻结存档**。因为剔除后重新拟合，模型自然不再报这些指标越界；若不冻结而是每次重新推导，系统会读到"没有越界项"从而把它们又放回模型——淘汰理由消失、审计链断裂。

### 环节 2.6 · Assemble master data（组装主数据）— 计算执行

**做什么**：把闯过全部六层的指标组装成建模直接消费的**主特征宽表**。

**人看到什么**：产物由五部分组成——
- **建模对象卡片**：每个对象的数据月数、特征列数、哪个指标作 Y；若某个对象无法组装则显示原因，**单个对象失败不会拖垮其余对象**。
- **入选清单**：每个存活指标及其完整 L1–L4 路径。
- **淘汰清单**：每个被移除的指标，标明**死于哪一层**、原因、以及**逐层裁决全链路**——没有任何东西悄无声息地消失。
- **过滤漏斗**：六段式流失报告，每段显示 进入 → 淘汰 → 存活，并列出该层具体拿掉了哪些指标；可点击某一层查看明细。
- **切片菜单**：品牌 / 渠道类型 / 渠道 / 省份组 / 时间粒度 / 指标子集——**这些选项从存活数据里现算**，所以不会出现选了却查不到数据的死选项。

**宽表怎么呈现**：宽表**不预先固化在产物里**，而是按人选择的切片**实时计算**（一行一期，第一列是期次，其次是 KPI 列，其余指标按字母序）。原因很实际：把所有维度组合都预生成体量巨大，而且任何一个裁决一变就全部过期。表格上限 400 行 × 60 列，超出时会明确标注"仅显示最近 400 期 / 前 60 个指标"，**不做无声截断**。

**两个正确性细节**：
- **被解释变量（KPI）会被显式放行**——它从来没有被任何过滤层裁决过，若不特别放行，表里就会丢掉 Y。默认取销量型 KPI，与 OLS 的默认 Y 保持一致。
- **每个指标按自己的规则汇总**：比例/覆盖率类跨地区取**平均**，花费与销量类**求和**。用一套统一规则会把百分比跨地区相加，得出荒谬的数字。

**底层逻辑**：整张表只认一份"最终裁定名单"——2.5y 确认的 Y + 2.5x 勾选的 X，再扣除各层淘汰项。试拟合、主数据表、正式训练三处**共用同一份名单**，杜绝各环节各算各的、导致训练时混入已淘汰数据。

---

### 环节 2.6d · Lock master data（锁定主数据）— 人的关卡

**怎么操作**：按品牌 × 渠道 × 区域 × 粒度切片抽查数据；核对漏斗——每个被淘汰的指标都能对上账、都能说清死因；确认无误后锁表。若认为变量选择还需再来一轮，可回退到 2.5 重新设置。

**底层逻辑**：**锁表必须是人的动作**——建模永远不应该在一张没人看过的表上启动。锁定之后，S4 建模阶段才被允许开始，且只能在这张锁定的表上训练。

## 四、贯穿始终的四条铁律

1. **数字永远来自真实计算，不来自 AI**。所有评分、统计量、回归结果、异常识别都由确定性计算产出；AI 的角色只有三个——**解读、提案、写理由**。AI 写的每一句都被限定字数、限定"仅基于给定数字"、并禁止编造事件与数字；返回值超出允许范围会被强制归位。**没有配置大模型时，整条流程照常跑完**，只是少了那几句自然语言点评。

2. **淘汰是继承的、不可逆流的**。任何一层的否决对后续所有层生效，被否决的指标绝不悄悄复活；界面上以划线锁定行明示"死于哪一层"。

3. **每一次放行都有人签字**。六个人工关卡（2.1 / 2.2d / 2.3s / 2.4d / 2.5y·x·p·r / 2.6d）确保 AI 只能提案，进入模型的每一份数据都经过人的裁决；主数据表必须由人亲手锁定。

4. **失败与局限如实呈现，不粉饰**。没有变量通过门槛时会直说"仅作起点，请复核再采信"；数据量不足以算多元共线时会注明"当前 VIF 只是两两近似"；表格截断会写明截断范围；被淘汰的变量一律照常列出而不是藏起来；每条经验带都标明来自你的行业知识包还是通用默认值。
